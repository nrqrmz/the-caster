## Global Constraints

- No build step, no bundler: native ES modules + Phaser 3 from CDN. (CLAUDE.md)
- Mobile-only, portrait. Logical resolution fixed at 480×854 (`GAME_WIDTH`/`GAME_HEIGHT` in `src/config.js`). Time fields in ms; lower is better. Stats are pre-scale starting values — `GameScene.spawnBoss` applies `scaleEnemyDef(def, this.diff)`. Exact HP is tuned in playtest (spec §4).
- Pure/Phaser split: boss defs (`src/data/bosses/air.js`) and tests have **no Phaser import** and are covered by `node --test`. `src/scenes/GameScene.js` is Phaser-coupled (verified by playtest).
- Texture/color keys are centralized in `src/config.js` (`TEX`, `COLORS`); reference them, never inline a key or hex. Air bosses reuse `TEX.miniboss`/`TEX.boss` and `COLORS.lightning`/`COLORS.boss`/`COLORS.miniboss`/`COLORS.ash` (all exist today).
- Tests use `node:test` + `node:assert/strict`. Run a single file with `node --test tests/<file>`; the whole suite with `node --test`.
- All bosses carry `elite: true` (resist CC — standard heritage).
- **Never inline a hex/texture string**: if a new tint is wanted for a form, add a `COLORS.*` key in a separate small commit; this plan reuses existing keys to stay scoped.

## Boss phase-step verb reference (executed by `executeAttack`/`think` today)

`do:` verbs already handled: `wait`, `shootStraight`, `shootSpread`, `nova`, `shootHoming`, `dashStrike`, `lobAoe`, `summon`. Step fields: `{ do, telegraph, dur, speed, damage, count, arc, radius, dps, duration, spawnType, cap, respawnMs }`. Step-level CC flags (`stun:true`, `lift:true`, `push:{force,ms}`) flow onto spawned shots via Plan 2's `executeAttack` passthrough (`shot.stunMs`/`shot.liftKind`/`shot.pushForce`/`shot.pushMs`); GameScene's caster-vs-shot overlap (Plan 1 Task 3) reads those fields and calls `applyCasterCc`/`applyCasterPush`. `drain` is a *modifier* on the def (resolved on melee/contact in GameScene, Plan 1 Task 3), not a step flag. `enter:['spawnTornado']` runs the `spawnTornado` boss hook on phase entry (Plan 1 Task 7).

## Design decisions captured up front (assumptions)

1. **Caballero de Sangre `evade`:** `evade` is a MOVEMENT, not a modifier (Plan 1 `MOVEMENTS.evade`). The spec text lists "modifiers `drain` + `evade`", but a bruiser cannot have two movements. **Decision: keep `movement: { type: 'charge', ... }` as the bruiser kit and give it only the `drain` modifier; the dodge is expressed by switching `movement` to `evade` in its Phase 2** (it stops being a pure charger and starts juking when low). This keeps one movement per phase, honors both the bruiser feel (P1) and the "esquiva tus orbes" feel (P2), and needs no engine change. Galahad's Humano form uses `evade` as its sole movement — the canonical dodge form.
2. **Miniboss death lines (Bruja "Ahora te enfrentarás a la tormenta…"):** the engine fires `onClear` dialogue only for the **templeBoss** phase (`GameScene.phaseStoryDialogue`), and `checkPhaseCleared` shows `this.runner.currentPhase().dialogue` for any boss phase if present. A miniboss level's phase can carry a `dialogue` array. **Decision: model the Bruja death line as the nv5 level's miniboss-phase `dialogue` (shown when the miniboss dies), keyed `story.air.bruja.death`.** This needs a tiny `makeBranch`/levelBuilder pass-through OR — to keep this plan scoped — we attach it as the nv5 level's clear dialogue. Since `levelBuilder` does not currently thread a per-miniboss `dialogue`, we keep the i18n key `story.air.bruja.death` defined and surface it as a **playtest/stretch note** (Task 6, Step 6.4): if `checkPhaseCleared` already renders `currentPhase().dialogue`, wiring it is a one-line levelBuilder change; otherwise it ships as a future hook. The string lands now so nothing else blocks.
3. **`_tornadoPhase`:** mirrors the whirlpool's `_whirlpoolPhase`, which is never set explicitly and defaults to `1` inside `runBossHook` (`typeof boss._whirlpoolPhase === 'number' ? boss._whirlpoolPhase : 1`). Plan 1's `spawnTornado` hook does the same: `const phase = typeof boss._tornadoPhase === 'number' ? boss._tornadoPhase : 1;`. **Decision: bump `_tornadoPhase` per boss phase via a tiny GameScene tweak in `_applyBossPhaseTornado` (Task 2)** keyed to `boss.def.key === 'elemental_tormenta'` — set `_tornadoPhase` from the active BossBrain phase index each frame so the Elemental's P2/P3 pull/radius escalate. This keeps the engine generic (default 1) and themes only the Elemental.

```js

  // fills by timer; periodic taunts float. On full: he becomes targetable and is
  // forced into his fight phase (stops summoning). Killing him then clears the level.
  updateRitual(delta) {
    const boss = this.boss;
    if (!boss || !boss.active || !boss.def || !boss.def.ritual || !boss._ritual) {
      if (this.ritualGfx) this.ritualGfx.clear();

    if (!this.ritualGfx) this.ritualGfx = this.add.graphics().setDepth(950);
    this.ritualGfx.clear();
    const frac = ritualFraction(boss._ritual);
    const bw = GAME_WIDTH - 80, bh = 10, bx = 40, by = 70;
    this.ritualGfx.fillStyle(COLORS.healthBack, 0.9);
    this.ritualGfx.fillRect(bx, by, bw, bh);
    this.ritualGfx.fillStyle(COLORS.lightning, 0.95);
    this.ritualGfx.fillRect(bx, by, bw * frac, bh);
    this.ritualGfx.lineStyle(2, COLORS.boss, 0.9);
    this.ritualGfx.strokeRect(bx, by, bw, bh);
  }

    const label = this.add.text(boss.x, boss.y - 40, text, {
      fontFamily: 'monospace', fontSize: '12px', color: '#fff176', align: 'center',
      wordWrap: { width: 200 },

    this.tweens.add({ targets: label, y: label.y - 28, alpha: 0, duration: 2200, onComplete: () => label.destroy() });
```

```js
  _beginBossTransform(boss) {
    boss._transforming = true;
    // Clear this form's adds.
    const live = this.enemies.getChildren().filter((e) => e.active && e !== boss);
    for (const e of live) e.destroy();

    if (feint) {

      const baseY = boss.y;
      this.tweens.add({ targets: boss, alpha: 0.2, scaleY: boss.scaleY * 0.3, y: baseY + 14, duration: 420, ease: 'Quad.easeIn' });
      this.flashCircle(boss.x, boss.y, (boss.def.radius || 26) + 12, COLORS.boss);

      boss.scaleY = boss.scaleX; // undo any collapse flatten before _applyBossForm resizes
      boss.y = boss.y; // (no-op; sprite re-applied below)
      boss._formSeq.completeTransform();

      // _applyBossForm already set the sprite/tint for the new form; only re-tint
      // here for the legacy (non-sprite) fallback path.
      if (!hasRecipe(boss.def.key)) {
```
