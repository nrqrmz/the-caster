# i18n / selector de idioma EN-ES — diseño

**Fecha:** 2026-06-16
**Estado:** aprobado (brainstorming)
**Sub-proyecto:** A de la tanda de ajustes previa a los mundos Aire/Tierra
(orden acordado: B dificultad ✅ → **A i18n** → C pixel art → D animaciones).

## Problema

Todo el texto del juego está hard-codeado en español, repartido en 10 escenas
(`add.text`/`setText`) y en datos (`regions.js` para narrador + nombres de nivel,
`shop.js`, `skilltree.js`, `bosses/water.js`, `levelBuilder.js`). El juego debe
ofrecer **inglés y español**, con menús y textos de narrador traducidos. Hacerlo
ahora —antes de escribir la narrativa de Aire y Tierra— evita pagar el costo de
traducir prosa nueva después.

## Decisiones (del brainstorming)

1. **Cuándo/dónde se cambia:** toggle **solo en el menú principal**; entrar a
   jugar fija el idioma de esa partida (opción C, la más simple).
2. **Idioma por defecto:** **autodetectar** de `navigator.language` en la primera
   visita; la elección se persiste.
3. **Dónde viven las traducciones:** sistema único **`t(clave)`** con archivos de
   idioma. Toda la UI y la narrativa se referencian por clave; `regions.js` deja
   de tener prosa literal.

## Arquitectura

### Capa i18n (módulo puro, sin Phaser, testeable)

**`src/i18n/index.js`**

- `detectLanguage(navigatorLang)` → `'es'` si el string empieza con `es`
  (case-insensitive); en cualquier otro caso (incluido `undefined`) → `'en'`.
- `getLanguage()` → idioma activo (`'es'` | `'en'`).
- `setLanguage(lang)` → fija el idioma activo y lo persiste vía storage inyectable.
- `initLanguage(navigatorLang, storage)` → al arrancar: si hay valor persistido
  válido lo usa; si no, `detectLanguage(navigatorLang)` y lo persiste. Devuelve el
  idioma resuelto.
- `t(key)` → resuelve `key` (notación punteada, p.ej. `'menu.play'`) en el locale
  activo. Si falta en el activo, cae al otro idioma; si falta en ambos, devuelve la
  clave literal y emite `console.warn`. (En práctica el test de paridad garantiza
  que nunca falte.)
- Persistencia: **clave dedicada** `localStorage['caster.lang']`, gestionada por
  este módulo con un `storage` inyectable (`getItem`/`setItem`), igual que
  `SaveSystem`, para testear con un fake. **Separada del save principal**: el
  idioma es preferencia de UI global, disponible antes de cargar cualquier save.

**`src/i18n/locales/es.js`** y **`src/i18n/locales/en.js`**

- Diccionarios de claves anidadas (objetos planos por namespace). Una sola fuente
  por idioma. Ambos deben tener **exactamente el mismo conjunto de claves**.

### Namespaces de claves

```
ui.*         // strings compartidos (p.ej. 'ui.tap', 'ui.back')
menu.*       // MenuScene
map.*        // MapScene
shop.*       // ShopScene (+ nombres de ítems de shop.js)
skill.*      // SkillTreeScene (+ labels de skilltree.js)
branch.*     // BranchScene (+ KIND_LABEL: 'Básico', etc.)
pause.*      // PauseScene
gameover.*   // GameOverScene
hud.*        // UIScene (HP, botón fireball, etc.)
speaker.*    // 'speaker.narrator', 'speaker.caster', 'speaker.unknown' (=???),
             // y nombres de mago por región (p.ej. 'speaker.mage.fire')
story.<region>.*  // narrativa: intro, mageLines, y dialogue.onEnter/onClear por nivel
region.<id>.name  // nombre mostrable de la región (p.ej. 'El Volcán'/'The Volcano')
```

### Integración con la narrativa (DialogueScene queda intacta)

`regions.js` guarda **claves**, no prosa:

```js
intro: ['story.fire.intro.0', 'story.fire.intro.1'],
mageLines: ['story.fire.mage.0', 'story.fire.mage.1'],
dialogue: { onClear: [
  { speaker: 'speaker.caster',  text: 'story.castle.5.clear.0' },
  { speaker: 'speaker.unknown', text: 'story.castle.5.clear.1' },
]},
```

La resolución a idioma ocurre **en el punto donde se lanza el diálogo**: la escena
que arma el payload para `DialogueScene` mapea las líneas a strings ya resueltos:

```js
const resolved = lines.map(l => ({ speaker: t(l.speaker), text: t(l.text) }));
this.scene.launch('Dialogue', { lines: resolved, onDone });
```

Así **`DialogueScene` no cambia**: sigue recibiendo y pintando `{ speaker, text }`
como strings. Lo mismo para `region.<id>.name` y los nombres de mago: se resuelven
con `t()` en el punto donde se muestran (mapa, branch, diálogo).

### Toggle de idioma (solo MenuScene)

- Control segmentado **`ES | EN`**: dos textos tappables, el activo resaltado.
- Tap en el inactivo → `setLanguage(otro)` → persiste → `scene.restart()` para
  repintar el menú en el nuevo idioma.
- No existe en ninguna otra escena.

### Arranque

- `main.js` llama `initLanguage(navigator.language, window.localStorage)` justo
  después de los imports y **antes** de `new Phaser.Game(config)`. Como las escenas
  solo corren su `create()` una vez que el juego arrancó, el idioma queda fijado
  antes de que se pinte cualquier texto. A partir de ahí toda escena lee `t()` en
  su `create()`.

## Flujo de datos

```
navigator.language / localStorage['caster.lang']
   → initLanguage() fija el idioma activo
   → escenas llaman t(clave) en create() → texto renderizado
toggle: tap → setLanguage(otro) → persiste → MenuScene.restart()
```

## Pruebas (`node --test`, módulo puro)

`tests/i18n.test.js` (nuevo):

1. **detectLanguage:** `'es-MX'`→`'es'`, `'es'`→`'es'`, `'en-US'`→`'en'`,
   `'fr-FR'`→`'en'`, `undefined`→`'en'`.
2. **initLanguage:** sin valor persistido → detecta del navigator y lo guarda en el
   fake storage; con valor persistido válido → lo usa e ignora el navigator.
3. **t():** devuelve el string correcto del locale activo; tras `setLanguage('en')`
   devuelve el inglés; `setLanguage` persiste vía fake storage.
4. **Fallback:** clave presente solo en un idioma → al estar activo el otro, cae al
   idioma que la tiene; clave inexistente en ambos → devuelve la clave literal.
5. **Paridad (clave del diseño):** `es.js` y `en.js` tienen el **mismo conjunto de
   claves** exacto (comparación profunda de rutas punteadas). Blinda traducciones a
   medias, incluida la narrativa de mundos futuros.

## Superficie de implementación

- **Crear:** `src/i18n/index.js`, `src/i18n/locales/es.js`, `src/i18n/locales/en.js`,
  `tests/i18n.test.js`.
- **Modificar (literales → `t(clave)`):** las 10 escenas — `MenuScene`, `MapScene`,
  `ShopScene`, `SkillTreeScene`, `BranchScene`, `PauseScene`, `GameOverScene`,
  `UIScene`, `GameScene`, y el lanzamiento de diálogos.
- **Modificar (literales → claves):** `regions.js` (intro, mageName, mageLines,
  dialogue por nivel, name de región), `shop.js`, `skilltree.js`, `levelBuilder.js`
  / `bosses/water.js` si exponen texto mostrable.
- **Arranque:** `main.js` / `BootScene` para `initLanguage`.
- **Sin cambios:** `DialogueScene` (recibe strings ya resueltos).

## Fuera de alcance

- Pixel art (C) y animaciones (D): sub-proyectos propios.
- Rebalanceo de dificultad (B): ya hecho.
- Más de dos idiomas; pluralización/género avanzados; formateo de números/fechas.
  (`t()` se diseña simple; si algún día se necesita interpolación de parámetros, se
  agrega entonces — YAGNI.)
- Traducción profesional/revisión de estilo del inglés: las traducciones iniciales
  las redactamos nosotros; un traductor podría refinarlas luego sobre los locales.
